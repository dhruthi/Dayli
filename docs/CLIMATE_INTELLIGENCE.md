# Dayli.ai Climate Intelligence Service Specs

## 1. Overview
The **Dayli.ai Climate Intelligence Service** decouples climate data sourcing, location resolution, normalization, deterministic risk evaluation, and hydration target calculations.

---

## 2. Architecture Overview

```
User Location / GPS / Shared WhatsApp Coordinates
                        ↓
                 Location Service
                        ↓
            Climate Service (Cache Check 10-min TTL)
                        ↓
            Provider Router & Strategy
            ├── Real Weather Provider (Open-Meteo / WeatherAPI)
            └── Mock Weather Provider (Micro-Zone Fallback)
                        ↓
              Climate Data Normalizer
                        ↓
            Normalized Climate Data Schema
             ├── Deterministic Health Risk Engine
             └── Deterministic Hydration Engine
                        ↓
            Personalized Climate Advice Engine
                        ↓
         Chat Engine & WhatsApp Message Formatting
```

---

## 3. Normalized Climate Data Schema

```typescript
export interface NormalizedClimateData {
  temperature_c: number;
  feels_like_c: number;
  humidity_percent: number;
  wind_speed_kmh: number;
  precipitation_mm: number;
  aqi: number;
  aqi_status: 'Good' | 'Moderate' | 'Unhealthy' | 'Severe' | 'Hazardous';
  uv_index: number;
  uv_status: 'Low' | 'Moderate' | 'High' | 'Very High' | 'Extreme';
  condition_text: string;
  timestamp: string;
  location: LocationInfo;
}
```

## 4. Deterministic Risk Thresholds

| Metric | Category Thresholds |
|---|---|
| **Heat Risk** | Low (<32°C) \| Moderate (32-37°C) \| High (37-41°C) \| Extreme (>41°C or Feels Like >45°C) |
| **Air Quality (AQI)** | Good (0-50) \| Moderate (51-100) \| Unhealthy (101-200) \| Severe (201-300) \| Hazardous (>300) |
| **UV Exposure** | Low (0-2) \| Moderate (3-5) \| High (6-7) \| Very High (8-10) \| Extreme (11+) |
| **Dehydration Risk** | Calculated based on heat index + humidity sweat loss obstruction |

---

## 5. Hydration Target Calculation Formula

```
Hydration Target (mL) = Base Weight Requirement + Pregnancy/Postpartum Surge + Thermal Heat Compensation + Activity Boost

- Base Weight Requirement: 35 mL per kg body mass (default 65kg baseline = 2,275 mL)
- Pregnancy Surge: 1st Trimester (+250 mL) | 2nd Trimester (+300 mL) | 3rd Trimester (+350 mL) | Postpartum (+700 mL)
- Thermal Heat Loss: Feels Like ≥45°C (+900 mL) | ≥40°C (+700 mL) | ≥35°C (+450 mL) | ≥30°C (+250 mL)
- Physical Activity: Moderate/Active (+400 mL)
```

> [!IMPORTANT]
> **Medical Guidance Disclaimer**: All hydration targets generated by the Hydration Engine are explicitly flagged as general climate health guidance and not guaranteed medical prescriptions.

## 6. Environment Variables

```bash
# Weather Provider Selection ("auto" | "real" | "mock")
WEATHER_PROVIDER_TYPE=auto
VITE_WEATHER_PROVIDER_TYPE=auto

# Optional Weather API Key (OpenWeatherMap / WeatherAPI)
WEATHER_API_KEY=your_key_here
VITE_WEATHER_API_KEY=your_key_here

# Climate Cache TTL in Minutes (Default: 10)
WEATHER_CACHE_TTL_MINUTES=10
VITE_WEATHER_CACHE_TTL_MINUTES=10
```

## 7. Automatic Fallback Strategy

If `RealWeatherProvider` experiences a timeout (>6000ms), invalid credentials, or network failure:
1. The error is caught gracefully.
2. The service switches to `MockWeatherProvider`.
3. The response metadata sets `sourceType: "mock_fallback"`.
4. The user chat interface never crashes or freezes.
